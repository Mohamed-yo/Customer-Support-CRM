## What this is

A customer support CRM. Staff manage customers, tickets, SLAs, a knowledge base, and reports. Customers use a self-service portal with live chat. Tickets also arrive from a web form and from email, WhatsApp, and SMS webhooks. The backend and frontend are separate apps with no shared code.

## Tech stack

- Backend: C# on .NET 8, ASP.NET Core Web API, EF Core 8 (SQL Server), SignalR
- Frontend: React 18, TypeScript (strict), Vite 8, React Router 6, Zustand 5, Tailwind 3, i18next (English and Arabic)
- Backend tests: xUnit with the EF Core InMemory provider
- Frontend tests: none
- Lint: oxlint (frontend only)

## Conventions

- TypeScript strict mode is on, along with `noUnusedLocals` and `noUnusedParameters`. Keep new code strict-clean.
- C# nullable reference types are on in both projects. Do not suppress nullable warnings without a reason.
- Authorization uses named policies: `RequireStaff`, `RequireCustomer`, and `RequireExternalClient`. A staff token must never satisfy a customer endpoint, and the reverse also holds. Add a policy to every new controller.
- Secrets stay blank in `appsettings.json`. Real values go only in the gitignored `appsettings.Development.json` or in environment variables.
- Add user-facing strings to both `frontend/src/i18n/locales/en.json` and `ar.json`.
- Schema changes go through `dotnet ef migrations add <Name>`. Never edit an applied migration.
- Run `npm run lint` and `dotnet test` before pushing.

## Gotchas

- No CI runs on this repo. Nothing checks a push or PR automatically, so run the commands above yourself.
- No coverage threshold exists. Backend line coverage is about 45% without the migrations. The frontend has no tests.
- The README is out of date. It describes a scaffold-only state that the code has moved past.
- CORS allows only `http://localhost:5173` (`Program.cs`). Change the Vite port and the CORS policy together.
- The Development seed creates a known admin login (`Data/SeedData.cs`). Never run a deployed instance with `ASPNETCORE_ENVIRONMENT=Development`.
- Outbound webhooks are sent synchronously inside the triggering request, with no retry.
- Business logic lives in the controllers, which query `AppDbContext` directly. Some controllers call static helpers on `TicketsController`.
- The backend has no `.editorconfig` or analyzer configuration, so C# style is not enforced.
